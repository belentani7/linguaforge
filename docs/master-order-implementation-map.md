## Veredicto de alcance

La orden maestra describe una plataforma educativa escalable, no solo una colección de pantallas. El proyecto actual ya tiene una base funcional de catálogo, rutas bidireccionales, niveles A1–C2, módulos, lecciones piloto, cuatro tipos de ejercicios, progreso persistido, diagnóstico, práctica, SRS, perfil, accesibilidad automatizada, documentación open source y producción publicada. No obstante, varios requisitos de la orden son objetivos de expansión y no deben presentarse como implementados: A0 como currículo completo, contenido por 90 pares, búsqueda/diccionario, audio y pronunciación completos, revisión experta, tráfico representativo y legalidad específica por proveedor.

## Decisiones de implementación

La orden se aplica reutilizando la arquitectura existente y evitando una reescritura masiva. Se priorizan contratos de datos, procedencia, estados vacíos honestos, pruebas de comportamiento y rutas que ya funcionan en producción. No se agregan tablas, widgets, audio, modelos IA o contenido únicamente para hacer crecer el inventario visual. Cualquier ampliación de datos debe llegar mediante un lote versionado, licencia verificable, atribución, normalización, deduplicación, validación por ruta/nivel/tema y revisión editorial.

La plataforma puede seguir creciendo durante años porque la dirección de aprendizaje es un dato (`sourceLanguage → targetLanguage`), los módulos y lecciones se relacionan con una ruta y un nivel, los ejercicios usan un modelo común y el backend expone procedimientos tRPC tipados. La expansión pendiente es principalmente de **contenido verificado, revisión pedagógica y operación**, no de duplicar pantallas por idioma.

## Gates que permanecen abiertos

El banco de 1000 entradas por par y los siete niveles pedagógicos no se marcarán como completos hasta procesar un export oficial íntegro. La búsqueda/diccionario, pronunciación y listening requieren fuentes y artefactos con licencias auditadas. La revisión jurídica específica, la validación de costes y rendimiento con tráfico representativo y la revisión asistiva manual permanecen fuera de una afirmación automática de 10/10.

## Mejora aplicada en esta iteración

Se añadió `content.search` como procedimiento tRPC público con validación Zod y consulta real sobre entradas de vocabulario, ejemplos, módulos y lecciones. El dashboard incorpora un widget de búsqueda con resultados etiquetados por licencia/procedencia y un estado vacío explícito cuando no hay coincidencias o la base no está configurada. No se presentan resultados generados ni se afirma que el buscador cubra conceptos gramaticales hasta disponer de un modelo de conceptos y datos correspondientes.
